CAN: the network
that never collides

How two wires let many electronic control units share one bus, and how we can prove every message arrives on time.

Open with a question: how many computers do you think are talking inside a modern car right now? Let the room guess. Whatever the number, most of them share the same pair of wires, and they never collide. Today we find out how, bit by bit, and how engineers prove the timing.

Davis et al., Real-Time Systems 35(3), 2007, §1.1 · Bosch CAN Spec. 2.0 (1991) · Hartwich, iCC 2012 · CiA, CAN XL

Before CAN, cars used point-to-point wiring: a dedicated wire for every connection. CAN replaced that harness with one shared bus. Bosch started in 1983, presented it to the SAE in 1986, and Mercedes put it in the 1991 S-Class. ISO standardised it in 1993. The second row is the modern story.

The big idea

A CAN frame has no destination address. Its identifier says what it carries and how urgent it is.

Every node hears every frame, and its acceptance filter decides what to keep. The identifier also sets the frame’s priority on the bus.

Bosch CAN Specification 2.0 (1991), Part B, “Basic Concepts”

The one sentence to remember. Ethernet asks “who is this for?” CAN asks “what is this, and how important is it?” You can add a node that listens to engine speed without changing anyone else. And because the identifier is the priority, arbitration comes for free.

02 · Physical layer (ISO 11898-2)

Dominant beats recessive

Dominant0≈ 3.5 V≈ 1.5 V≈ 2 V (> 0.9 V)

Wired-AND

One dominant transmitter overrides any number of recessive ones. Arbitration is built on this.

Watch the 3D model

Noise moves CAN_H and CAN_L together. Their difference (green) stays rock-steady.

common-mode noise on · Vdiff unchanged

CiA, “CAN HS transmission” · ISO 11898-2 · Bosch CAN Spec. 2.0, “Bus Values”

Recessive: nobody drives, both lines rest near 2.5 V. Dominant: CAN_H goes to about 3.5 V and CAN_L to about 1.5 V. Receivers only read the difference. In the model, the two lines bounce together because of noise, but the green difference line never moves. That is why CAN uses a differential twisted pair.

02 · Topology

One line, terminated at both ends

ECUs transmit at random · pulses travel both ways · 120 Ω at each end

Each node is a microcontroller with a CAN controller (framing, arbitration, errors) and a transceiver (voltages). The 120 Ω resistors match the cable impedance to stop reflections, and they pull the idle bus back to recessive.

ISO 11898-2 · CiA, “CAN HS transmission” · TI SLOA101B

Why not terminate inside every node? If that node is unplugged, the bus loses its termination. ISO 11898 puts one resistor at each end of the line. Keep the stubs short, because long stubs cause reflections at high bit rates.

03 · Data link layer

Anatomy of a data frame (11-bit ID)

Arbitration field

11-bit identifier + RTR (dominant = data frame, recessive = remote frame).

Control + data

IDE dominant marks the standard format. The 4-bit DLC gives 0–8 data bytes, sent MSB first.

Check + close

15-bit CRC, an ACK slot filled in by receivers, 7 recessive EOF bits, then 3 intermission bits.

Bosch CAN Specification 2.0 (1991), Part B, “Message Transfer”. Block widths follow bit counts (stuff bits not shown).

SOF is one dominant bit that hard-synchronises everyone. The CRC polynomial is x^15+x^14+x^10+x^8+x^7+x^4+x^3+1. The transmitter sends the ACK slot recessive, and any receiver that got the frame correctly overwrites it with dominant. Without stuff bits, an 8-byte standard frame is 111 bits including the intermission.

03 · Medium access

Bitwise arbitration: the lowest ID wins

SOF · ID10 → ID0 · RTR

The rule

Every transmitter reads back each bit. If it sent recessive (1) and reads dominant (0), it has lost. It stops at once and becomes a receiver.

Non-destructive

0x123 drops at ID8 and 0x067 at ID1. 0x065’s frame is never corrupted, so no bus time is lost.

Tie-breakers

Same ID: a data frame beats a remote frame. Same base ID: a standard frame beats an extended one.

Bosch CAN Specification 2.0 (1991), Part B, “Basic Concepts” and “Message Transfer”

Tall cyan cubes are dominant 0s and low dim cubes are recessive 1s. Watch the orange cube: a node that sent recessive while the bus was dominant. Its row fades out, and it becomes a receiver. Act it out with three volunteers first, then show this.

04 · Error detection

Bit stuffing and five error checks

Frame bits: 0 0 0 0 0 0 0 1 On the bus: 0 0 0 0 0 1 0 0 1

After five identical bits, the transmitter inserts one opposite bit, and receivers remove it. This guarantees edges for resynchronisation. Stuffing covers SOF through the CRC sequence.

Residual risk of an undetected corrupted message: below message error rate × 4.7·10⁻¹¹.

ErrorDetected when …
BitA transmitter reads back a different bit (except during arbitration and in the ACK slot)
Stuff6 equal bits in a row in a stuffed field
CRCThe computed CRC differs from the received one
FormA fixed-form field holds an illegal bit
ACKThe transmitter sees no dominant ACK slot

Bosch CAN Specification 2.0 (1991), Part B, “Bit Stream Coding” and “Error Handling”

Stuffing gives the receivers edges to keep their clocks in step, and it turns six equal bits into an alarm. That is why the active error flag is six dominant bits: it deliberately breaks the rule so every node notices. The frame is destroyed for everyone and retransmitted automatically.

04 · Fault confinement

A faulty node removes itself

TEC = 0
StateCondition
Error-activeTEC ≤ 127 and REC ≤ 127. Signals errors with 6 dominant bits
Error-passiveTEC or REC ≥ 128. Signals with 6 recessive bits and waits 8 extra bits after transmitting
Bus-offTEC ≥ 256. Takes no part in bus activity. Rejoins after 128 × 11 recessive bits, with counters reset
CountersTX error +8 · RX error +1 · success −1

Bosch CAN Specification 2.0 (1991), Part B, “Fault Confinement”

The model replays a broken transmitter. Every error adds 8 to TEC. After 16 errors it reaches 128 and turns error-passive. After 32 it reaches 256 and goes bus-off, and the rest of the bus keeps running. Then it waits for 128 × 11 recessive bits and comes back with fresh counters.

05 · Bit timing

Inside one bit: 16 time quanta

SYNC 1 · PROP 7 · PHASE_SEG1 6 · PHASE_SEG2 2 → sample point 87.5 %

Hard sync

At SOF, the recessive-to-dominant edge restarts every node’s bit timing.

Resync

Later edges lengthen PHASE_SEG1 or shorten PHASE_SEG2 by up to SJW (1–4 TQ).

Distance limit

PROP_SEG must cover the round-trip delay. Longer bus, lower bit rate.

Bosch CAN Spec. 2.0, Part B, “Bit Timing Requirements” · ISO 11898-1 (Phase_Seg2 programmable on its own, minimum range 2–8 TQ)

The laser sweeping across the bit is the node’s clock. The flash is the sample point at 87.5 %. Bosch 1991 tied PHASE_SEG2 to PHASE_SEG1; ISO 11898-1 lets it be set on its own, which makes late sample points like 87.5 % possible.

Davis, Burns, Bril, Lukkien, Real-Time Systems 35(3):239–272, 2007, Eqs. 1–2

Messages are the tasks, the identifier is the fixed priority, and the bus is a single processor. A frame can’t be interrupted once it starts, so a high-priority message can be blocked by at most one lower-priority frame. Check the formula live: 34 + 64 + 13 + 24 = 135.

06 · A lesson from research

The 1994 analysis was optimistic

A, B and C each take 1 ms. A repeats every 2.5 ms. B and C repeat every 3.5 ms, with a 3.25 ms deadline. All three are released at t = 0.

3.0 ms

Original analysis (first instance only): looks safe

3.5 ms

True worst case: C’s second instance, released at 3.5, ends at 7.0

> 3.25 ms

Deadline missed. Also: deadline-monotonic isn’t optimal for CAN; Audsley’s OPA is

Davis, Burns, Bril, Lukkien, Real-Time Systems 35(3):239–272, 2007 (doi:10.1007/s11241-007-9012-7)

Watch the timeline build. C’s first instance finishes at 3 ms, inside its deadline. But C’s second copy is released at 3.5 while the bus is still busy. A and B go first, and C ends at 7.0: a 3.5 ms response against a 3.25 ms deadline. The 1994 analysis only checked the first instance. Science corrects itself.

Arbitration still runs slowly enough that every node agrees on each bit. The trick is to speed up only after arbitration is won: that is the BRS bit. CAN XL separates priority from addressing.

Three things to remember

1 · The identifier is the priority. Arbitration never wastes a bit.

2 · Errors are detected globally and confined locally.

3 · Timing is provable, but only with correct analysis.

Bosch CAN 2.0 (1991) · Davis et al. (2007)

Close the loop with the opening question. Arbitration explains “no collisions”, fault confinement explains robustness, and response-time analysis explains why we trust CAN with brakes and airbags. End on: “Prove it.”
